# ربط OTP والاستضافة النهائية لتطبيق «حساب»

## قرار OTP

> يعتمد الربط في الخلفية على واجهة `OtpProvider`. لا تخزن الخدمة رمز مزود خارجي في قاعدة البيانات، بل تحتفظ فقط بمرجع طلب التحقق ونتيجته، بينما يظل التحقق النهائي عند مزود OTP.

تدعم واجهة Twilio Verify قناتي SMS وWhatsApp ضمن تدفق واحد لإنشاء التحقق وفحصه. تُظهر إرشادات اليمن دعم إرسال SMS مع رمز البلد `+967`، لكن يجب فتح البلد في Geo Permissions لحساب Verify ثم التحقق من التسليم بأرقام تجريبية فعلية قبل فتح الخدمة للجمهور. [1] [2]

تصلح WhatsApp كقناة ثانية بعد نجاح SMS، لا كبداية إجبارية. تتطلب رسالة OTP عبر WhatsApp Sender خاصاً بالعلامة ومربوطاً بحساب WhatsApp Business؛ كما أن Meta تطلب Authentication Template لرموز التحقق. [1] [3]

| المرحلة | القناة | سبب القرار | شرط الانتقال |
|---|---|---|---|
| التجريب المغلق | SMS عبر Twilio Verify | أقل عدد من مكونات الإعداد، وتحقق خادمي موحد | تسجيل نجاح التسليم والتحقق لأرقام +967 حقيقية |
| التوسع الأول | SMS مع خيار WhatsApp | مسار بديل عندما يكون اتصال البيانات متاحاً | إكمال توثيق WhatsApp Business وربط Sender العلامة |
| النشر العام | قناة مفضلة للمستخدم مع fallback مدروس | يقلل فشل التحقق ويحافظ على تجربة عربية بسيطة | مراقبة النجاح والفشل والحد من الإساءة لمدة تشغيل تجريبي مستقرة |

## طبقة الأسرار والأمان

يضاف حساب Twilio من خلال أسرار بيئة الاستضافة فقط: `TWILIO_ACCOUNT_SID` و`TWILIO_AUTH_TOKEN` و`TWILIO_VERIFY_SERVICE_SID`. يضبط `OTP_PROVIDER=twilio` و`TWILIO_VERIFY_CHANNEL=sms` في بيئة التجريب. لا تدخل هذه القيم في GitHub أو ملف Flutter أو صورة Docker.

يمنع الخادم تشغيل `OTP_PROVIDER=development` في الإنتاج، ويشترط بيانات Twilio كاملة عندما يختار Twilio. يظل حد طلب OTP خمس محاولات لكل رقم خلال خمس عشرة دقيقة، كما يظل حد فحص الرمز خمس محاولات لكل تحدٍّ. يجب إضافة طبقة rate limit على مستوى عنوان IP في بوابة الاستضافة قبل الإطلاق العام.

## مقارنة الاستضافة

| النهج | المزايا والملاءمة | التنازلات | مدى الإعداد |
|---|---|---|---|
| Render مع خدمة Docker وPostgreSQL مُدار | يقبل Dockerfile الحالي، يدعم أوامر ما قبل النشر للترحيلات، النطاقات المخصصة، والنشر دون توقف. [4] | يتطلب حساباً مستقلاً وإدارة الأسرار وقاعدة بيانات مدارة مناسبة للخطة | منخفض إلى متوسط |
| DigitalOcean App Platform مع Managed PostgreSQL | يفصل التطبيق عن قاعدة بيانات مدارة، ويسمح بقصر اتصال القاعدة على التطبيق من Trusted Sources؛ وتوصي وثائقه بالقاعدة المدارة للإنتاج. [5] | يحتاج حساب سحابي وإعدادات شبكة ونطاق ومدفوعات منفصلة | متوسط |
| Railway مع PostgreSQL داخلي | سريع للتجريب المغلق؛ يوفر `DATABASE_URL` وخدمة PostgreSQL داخل المشروع. [6] | قالب PostgreSQL موصوف بأنه غير مُدار، لذا لا أعتمده كمرجع وحيد لقاعدة بيانات تجارية حساسة قبل تثبيت النسخ والاستعادة والمراقبة | منخفض للتجريب، متوسط للإنتاج |

الاختيار المبدئي هو **DigitalOcean App Platform مع Managed PostgreSQL** للإنتاج، لأنه يتيح عزل API عن قاعدة البيانات وربط التطبيق كمصدر موثوق. أما Render فيبقى بديلاً جيداً إذا أُعطيت الأولوية لإعداد Docker مباشر وبسيط. لا يُنشر أي خيار من دون قاعدة مدارة ونسخة احتياطية مجربة واستعادة معزولة.

## خطوات النشر التجريبي

أولاً، ينشأ مشروعان مستقلان: `hisab-staging` و`hisab-production`. لكل مشروع قاعدة PostgreSQL مستقلة، وأسرار JWT مختلفة، وخدمة API مستقلة، وسجل مراقبة مستقل. لا تنسخ قاعدة التجريب فوق الإنتاج ولا تستخدم مفاتيح OTP نفسها بينهما.

ثانياً، تنشأ قاعدة PostgreSQL المدارة في أقرب منطقة متاحة مناسبة، ثم تضاف خدمة Docker من فرع GitHub `feat/production-foundation-api`. تُضبط متغيرات البيئة السرية، وتنفذ ترحيلات قاعدة البيانات مرة واحدة قبل استبدال إصدار API. يربط فحص الصحة بمسار `/health`، ثم يضاف نطاق فرعي تجريبي مثل `api-staging.example.com` مع HTTPS.

ثالثاً، تفتح Twilio Geo Permissions لليمن، وينشأ Verify Service مخصص لـ«حساب». تُحفظ بياناته في بيئة التجريب فقط، ويختبر طلب رمز والتحقق منه لرقم يمني مملوك للفريق. بعد نجاح ذلك، تكرر العملية في بيئة الإنتاج بأسرار مستقلة.

رابعاً، قبل فتح التسجيل، ينفذ اختبار استعادة لنسخة PostgreSQL في قاعدة معزولة، واختبار OTP بفشل متعمد، واختبار تدوير refresh token، واختبار مزامنة أمر مكرر. لا يعتبر النطاق جاهزاً إذا نجح الإرسال فقط؛ يجب أن تنجح دورة التحقق والجلسة والمزامنة كاملة.

## المعلومات اللازمة لإكمال الربط الحقيقي

نحتاج حساب Twilio Verify مُفعلاً أو اختيار مزود بديل، وحساب الاستضافة المختار، واسم نطاق أو نطاق فرعي، ومفاتيح الوصول التي ينشئها المالك. تُدخل الأسرار مباشرة في مدير أسرار الاستضافة، ولا تُرسل في رسالة أو تحفظ في ملفات المشروع.
