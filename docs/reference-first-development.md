# بروتوكول التطوير المرجعي لتطبيق حساب

## الغرض

يستخدم «حساب» مرجع «فرصتك الذهبية» لفهم **المفاهيم التشغيلية** المناسبة لتطبيق Flutter متصل بالسوق المحلي. لا يعد المرجع مصدراً للكود أو للأسماء أو للأصول أو للإعدادات. كل تطبيق في «حساب» يبقى مستقلاً في التصميم والتنفيذ والهوية.

## بوابة بدء أي ميزة

قبل كتابة كود ميزة جديدة، يوثّق طلبها في وصف قصير يجيب عن السؤال التالي: ما الحاجة الفعلية للمستخدم، وما الإشارة العملية المشابهة في المرجع إن وجدت، وما أقل تصميم آمن وقابل للاختبار يحققها؟ ثم يحدد مالك بياناتها، وحالات الفشل، والسلوك دون اتصال، ومعيار القبول والاختبارات المطلوبة.

إذا لم تظهر إشارة مناسبة في المرجع، لا تُنشأ تبعية أو طبقة جديدة إلا بعد توضيح سببها وأثرها على الأداء والخصوصية والصيانة. لا تنسخ أسماء الملفات أو الكلاسات أو النصوص أو المعرفات أو نقاط النهاية أو الأصول من المرجع.

## خريطة الاعتماد

| مفهوم مرصود في المرجع | تطبيق مستقل في حساب | المرحلة | شرط القبول |
|---|---|---|---|
| إشعارات سحابية | تنبيهات للديون والمخزون والمزامنة عبر واجهة خدمة مستقلة | بعد اكتمال الهوية والخلفية | لا يطلب الإذن إلا عند وجود قيمة واضحة، وتُختبر حالة الرفض |
| مشاركة الملفات | مشاركة فاتورة أو تقرير PDF مؤقت عبر واجهة النظام | بعد تثبيت الفواتير والتقارير | لا يشارك الملف قبل اكتمال توليده والتحقق من هوية المستخدم |
| روابط عميقة | رابط جديد خاص بحساب لمشاركة فاتورة أو دعوة مقيّدة الصلاحية | بعد إصدار API آمن | يعمل الرابط دون كشف بيانات حساسة أو تجاوز صلاحيات المستخدم |
| عمل مؤجل وتخزين محلي | طابور مزامنة مستقل وقابل لإعادة المحاولة للمعاملات المحلية | مع الخلفية المركزية | العملية محلية أولاً ولا تُعلَّم متزامنة إلا بعد إقرار الخادم |
| اختيار الصور | مرفق منتج أو إثبات عملية عند وجود حاجة تشغيلية موثقة | مرحلة لاحقة | قيود واضحة للحجم والنوع وحذف الملفات المؤقتة |

## ما لا نعتمده تلقائياً

لا تعد صلاحيات الموقع أو جهات الاتصال أو الميكروفون أو الخدمة الأمامية أو الإعلانات مؤشراً على حاجة «حساب» إليها. لا تطلب هذه الصلاحيات إلا بميزة موثقة، وموافقة مفهومة، واختبار للرفض، ومراجعة خصوصية.

## الوضع المعماري الحالي

يملك «حساب» أساساً جيداً يتضمن فصل `core` و`domain` و`data` و`presentation`، وRiverpod لتركيب الاعتمادات، وDrift للبيانات المحلية وترقياتها، ومسار مزامنة أولي، ونظام تنقل وثيم عربيين. الإضافة الأهم في الحزمة الحالية هي حفظ العملة وسعر الصرف والقيمة الأساسية للمعاملة.

الأولوية التالية ليست إعادة كتابة شاملة، بل تثبيت الحدود الناقصة تدريجياً: هوية حقيقية بدلاً من OTP التطويري، تخزين آمن للرموز، إعدادات بيئة منفصلة، عقود DTO ومحوّلات صريحة للشبكة، وطابور مزامنة مزود بمعرفات إيديمبوتنت وسجل أخطاء قابل للرصد.

## اختبار الجودة

كل ميزة تتضمن اختباراً لوحدة النطاق، واختباراً لمسار البيانات أو الخطأ عند الحاجة، واختبار واجهة للتدفق الذي تلمسه. يمر التغيير عبر التحليل الساكن والتنسيق واختبارات المشروع قبل رفعه، ولا يضاف Package إلا بعد مبرر ونطاق صغير وخطة إزالة أو بديل إن أصبحت غير مدعومة.
